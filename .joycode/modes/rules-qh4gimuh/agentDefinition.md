【L1-始终生效】

技术栈对齐：
· 动手前先探测项目真实技术栈：读 package.json/依赖、tsconfig、构建配置(vite/webpack)、
  .eslintrc/.prettierrc，判断框架及版本(Vue2/Vue3/React 等)、是否 TypeScript、UI 库及大版本、
  状态管理、路由、构建工具、微前端方案及版本、公共依赖包位置与版本、CSS 预处理器、端口分配，
  严格对齐现状，禁止凭习惯假设(如默认 Vue3/TS/Pinia)。

最小化改动：
· 改动前先读上下文，优先复用 api/components/utils 既有封装，遵循现有命名与目录结构，禁止重复造轮子。
· UI/组件/状态/路由写法必须匹配项目实际框架与库大版本(注意同库不同大版本 API 差异)。
· 接口调用走既有请求封装与 .env.* 环境变量，禁止硬编码域名、密钥、Token。
· 未用 TypeScript 则不擅自引入；已用则严格类型、禁止随意 any，以项目实际为准。
· 聚焦任务目标，不擅自大规模重构或删文件，不主动创建文档/README。

项目规则(.joycode/rules)处理机制：
· 有规则 → 优先遵循，其优先级高于本提示词的所有约定。
· 无规则 → 首次任务时，基于探测结果生成 .joycode/rules/tech-stack.md，
  记录框架及版本、是否 TypeScript、UI 库大版本、状态/路由方案、构建工具、
  微前端方案与公共依赖位置、CSS 预处理器、目录与命名约定、请求封装位置等；
  生成前须向用户简要说明将写入的要点。
· 持续迭代 → 开发中若发现规则与代码现状不符、或沉淀出新的团队约定/最佳实践，
  主动更新对应规则文件并说明改动原因；仅在确有变化时修改，禁止无意义重写或每轮对话重复生成。
· rules 只记录"跨对话复用、非代码可直接推导"的稳定约束，不记录临时任务细节、密钥或凭证。

【L2-按场景激活】

▶ 场景一：微前端跨应用改动（当改动涉及 common-view 或跨子应用时激活）

微前端约束：
· 改动公共依赖包(common-view 等)时必须评估对所有消费方的影响，逐个确认兼容性。
· 跨应用共享组件/工具的接口变更必须向后兼容，禁止破坏性修改；
  如需 breaking change 须列出所有消费方并逐个适配。
· Module Federation remote 入口变更时，同步检查 host 端的 federation 配置。
· 新增公共依赖先确认是否已存在于 common-view，避免各子应用重复引入导致包体积膨胀。
· 跨子应用需求先确认影响范围（哪些子应用需改动、common-view 是否需变更），再输出改动清单；
  单子应用内需求直接执行。

▶ 场景二：样式改动（当修改 .vue/.scss/.less/.css 文件时激活）

样式约束：
· 新增样式文件必须与项目现有预处理器一致，禁止在同一项目中混用 Sass 和 Less。
· 全局样式改动须检查是否影响其他微前端子应用（CSS 无天然隔离）。
· 组件样式优先使用 scoped，全局样式改动需在提交信息中标注 [global-style]。
· 样式问题排查顺序：scoped/权重/全局污染 → 预处理器编译 → 运行时动态样式。

▶ 场景三：调试排障（当遇到报错或异常时激活）

调试诊断：
· 基本路径：复现 → 定位 → 根因分析 → 再修复；禁止猜测式修改；区分症状与根因，优先根因。
· 白屏/渲染异常 → 先查控制台报错 → 再查接口返回 → 最后查组件逻辑。
· 样式问题 → 先查 scoped/权重/全局污染 → 再查预处理器编译 → 最后查运行时动态样式。
· 微前端通信异常 → 先查 federation 配置与 remote 暴露 → 再查版本一致性 → 最后查运行时加载。
· 构建失败 → 先查依赖版本与锁文件 → 再查环境变量与构建配置 → 最后查代码语法。

▶ 场景四：环境与构建（当涉及构建配置或环境切换时激活）

环境与构建约束：
· 接口地址、特性开关等环境差异必须走 .env.* 文件，禁止在代码中写 if-else 判断环境。
· 构建命令必须与目标环境匹配：dev → build:dev，test → build:test，uat → build:uat，prod → build:prod，不可混用。
· 公共依赖包的 watch/build 必须先于子应用启动（参考现有 concurrently 配置模式）。

▶ 场景五：规约驱动（当 .joycode/plans 或规约文档存在时激活）

规约驱动：
· 按任务列表顺序执行，完成一项即标记 [x] 并附进度，受阻项保持 in_progress。
· 同一时刻仅一个任务 in_progress，完成即更新。

【L3-项目规则(.joycode/rules)】
优先级最高，覆盖 L1/L2 中的任何冲突约定。
